# Bible Quest — Design Document

**Status:** Draft v0.2 (mobile-first, AI-built) · **Date:** 2026-11-10

---

## 1. Overview

Bible Quest is a 2D side-view, turn-based RPG where a single hero journeys through the Bible, starting in Genesis. Every encounter has two parts:

1. **Scripture intro.** One or two verses are read aloud while the text scrolls across the bottom of the screen and the hero runs across the landscape.
2. **Battle.** A turn-based fight against a themed foe. Before each of the hero's attacks, the player answers a question about the verse they just heard. A correct answer **powers up** the attack.

The game teaches Scripture through repetition and recall, wrapped in a combat loop that's fun on its own.

### 1.1 Goals

- Get players reading and _remembering_ Scripture: questions always come from the verse just read.
- **Mobile-first:** the primary product is an iOS and Android app, played in landscape and one-handed where possible. Web is a dev/test target, not the main product.
- Keep battles short (60–120 s) so they fit short phone sessions.
- Work fully offline: all Scripture, questions, art, and narration are bundled in the app.
- **Mostly written by AI:** code, tests, question drafts, and narration audio are produced by AI agents (Claude Code), with a human reviewing and approving. See §11.
- Walk through the Bible in canonical order, starting at Genesis 1:1.
- Be suitable for all ages: no gore, and nothing that mocks Scripture.

### 1.2 Non-goals for v1

- Multiplayer, PvP, gacha, or monetization systems.
- A party of several heroes. There is **one playable character**.
- Questions generated by an LLM at runtime. All content is authored and reviewed ahead of time (see §6).

### 1.3 Visual reference

The target _layout and feel_ is the screenshot the project started from: a side-view battlefield, the hero on the left facing the foe on the right, a wave indicator at the top (skull pips), floating damage numbers, and a hero portrait with an HP/energy bar at the bottom.

> **Art direction note:** that layout is our reference only. All characters, foes, backgrounds, and UI art must be **original or properly licensed**, in a bright cartoon/chibi style of our own. We will not copy art, characters, or UI assets from any existing game.

## 2. Core Gameplay Loop

```
┌────────────┐   ┌──────────────────┐   ┌───────────────────────────────┐   ┌──────────┐
│  World Map │──▶│  Scripture Intro │──▶│  Battle (1–3 waves)           │──▶│ Victory  │
│  (chapter  │   │  verse read aloud│   │  ┌─ Question ─▶ Hero attack ─┐│   │ recap +  │
│   select)  │   │  text scrolls,   │   │  │  (right = powered up)     ││   │ rewards  │
└────────────┘   │  hero runs ▶     │   │  └──────── Enemy turn ◀────┘ │   └──────────┘
      ▲          └──────────────────┘   └───────────────────────────────┘        │
      └──────────────────────────────────────────────────────────────────────────┘
```

### 2.1 Scripture intro scene

| Element      | Behavior                                                                                                                                                                                                                           |
| ------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Background   | Parallax layers (sky, far hills, near ground) scroll left to suggest running.                                                                                                                                                      |
| Hero         | Run-cycle animation. The hero moves from the left edge toward the center/right over the length of the reading.                                                                                                                     |
| Verse text   | A banner along the bottom with a semi-opaque backdrop. Text scrolls right to left like a news ticker, and the scroll speed is synced to the narration length. Reference shown (e.g. _Genesis 1:1–2_).                              |
| Narration    | Audio reads the verse. Recorded clips (one per verse, Kokoro "Bella" voice, `scripts/audio/narrate.py`) play when they match the verse text; any other verse is read by the device's TTS.                                          |
| Glowing orbs | While the verse is read, glowing **Armor orbs** float up along the hero's path. Tapping an orb unlocks that special attack **for the upcoming fight only**. See §2.6.                                                              |
| Controls     | **Skip** (after the first time the verse is heard; skipping forfeits any orbs not yet collected), **Replay** (uncollected orbs appear again), and **Show full text** (a static readable panel for slow readers and accessibility). |
| Exit         | When narration ends, the hero reaches the foe and the scene cross-fades into battle.                                                                                                                                               |

### 2.2 Battle

- **Turn-based:** Hero turn → Enemy turn → repeat.
- **Waves:** 1–3 foes per encounter, shown as pips at the top of the screen (our own icon, not skulls copied from the reference).
- **Hero turn:**
  1. **Choose an action** from the action bar: **Attack**, one of the **special attacks** unlocked by orbs this fight (§2.6), or the **Faith Ultimate** when the Faith meter is full.
  2. A question card slides in (it pauses combat). The Faith Ultimate skips this step, because it was already earned by answering questions.
  3. The player answers. Formats are multiple choice (4 options), true/false, or "fill in the missing word".
  4. **Correct:** the action's **powered** version: Attack does 3× damage, a special has its full effect, special VFX play, and the Faith meter gains +1.
  5. **Wrong:** the action's **base** version: Attack does 1× damage and a special has its weaker effect. The correct answer is shown with the relevant phrase of the verse highlighted. Learning comes first, so there is no extra punishment.
  6. _Optional, setting-controlled:_ a timer (off by default, 20 s when on). Answering fast gives a small bonus but is never required.
- **Faith meter:** +1 for each correct answer, plus a +1 bonus for 3 correct in a row. Wrong answers don't drain it. At 5 it is full and the **Faith Ultimate** is ready (§2.6). The meter carries across waves within a fight and resets after each fight.
- **Enemy turn:** the foe attacks on simple timing; damage is fixed per foe with light variance.
- **Lose state:** if hero HP reaches 0, the hero falls, the HUD fades and the camera zooms in on the hero. The screen goes black except for a dim beam of light from the sky onto the hero. The player prays the start of the Lord's Prayer (Matthew 6:9-10, retold in `core/content/prayer.ts`), tapping once for each phrase; the beam brightens with each one. Then the hero rises at full life ("Full of life again!") and the screen fades to the map. There is no permanent loss: nothing is saved on a defeat, and the next try at the passage rolls differently.

### 2.3 Question pool per encounter

- Each encounter needs **at least 6 questions** so a fight with several turns doesn't repeat too quickly. Questions are shuffled without replacement and recycled only if the pool runs out.
- **Short fights (2026-11-20):** foes have less HP and hit harder, and a right answer hits for 3×, so the first two foes fall to one right answer each and a fight at 60% accuracy takes about 5 questions (the balance test keeps the median at 3–6). The save remembers which questions were asked (`asked`); the next fight on a passage asks the unasked ones first, and the list for a passage starts over once all of its questions have been asked.
- Questions must be answerable **from the verse(s) just read**. This is a hard content rule that we check in review.
- Difficulty tags (`easy` / `medium` / `hard`) let a future difficulty setting filter the pool.

### 2.4 Foes (theming)

To keep combat age-appropriate and theologically careful, foes are **personified obstacles, chaos, and temptations, not biblical people**. Examples for Genesis:

| Passage                           | Foe concept                                       |
| --------------------------------- | ------------------------------------------------- |
| Gen 1:1–2 (formless and void)     | _Shade of the Deep_: a swirling darkness creature |
| Gen 3 (the Fall)                  | _The Serpent_                                     |
| Gen 3:17–18 (thorns and thistles) | _Thornbeast_                                      |
| Gen 6–8 (the Flood)               | _Flood Surge_: a water elemental                  |
| Gen 11 (Babel)                    | _Tower Golem_                                     |

This is an open question for review: confirm the tone with the stakeholders (see §10).

### 2.5 Progression (Phase 5+)

- **Chapters** map to Bible books; **stages** map to passages.
- Stars per stage (1–3) based on how many questions were answered correctly.
- ~~A light upgrade track bought with stars~~ (replaced 2026-11-20 by runes, below). Stars are now only a score per passage. No grinding is required to keep reading forward.
- **Runes (2026-11-20):** each passage awards one rune the first time it is won (`rune` in its encounter file, shown on the victory panel). The hero's four items each have **2 rune slots**, and each rune fits **one item only**, colour-coded (and shape-coded, for colour-blind players) by item: each item's runes are one pixel-art crystal (CraftPix crystals pack, see `art/README.md`) with the rune's mark on a badge. The sword is carried from the start; the other items' slots open when the angel gives that armor, and runes for them wait in the rune bag until then. A new rune goes straight into a free slot of its item (and runes waiting for an item go in when it is earned), so a player who never opens the Equipment screen still benefits. The Equipment screen (🛡️ Equipment on the map; scene key `runes`) opens on one button per item; tapping one shows that item's two slots and only the runes that fit it. Tapping a rune sets it in a free slot (when both are full, tap a slot next to swap it in), and tapping a set rune takes it out. Rules: `core/progress/runes.ts`; catalog and numbers: `core/battle/runes.ts` (drafts, checked by the balance simulation).

  | Item (gem)                    | Rune     | Effect (per rune; two stack)              |
  | ----------------------------- | -------- | ----------------------------------------- |
  | Sword (red ruby ◆)            | Might    | +1 attack                                 |
  |                               | Zeal     | Hits after a right answer land 25% harder |
  | Shield (blue sapphire ⬣)      | Life     | +20 max HP                                |
  |                               | Guarding | Start each fight with 1 shield block      |
  | Breastplate (green emerald ■) | Mending  | Breastplate heals 40% more                |
  |                               | Renewal  | Heal 3 HP on each right answer            |
  | Sandals (gold topaz ▲)        | Haste    | Start each fight with +2 energy           |
  |                               | Peace    | Sandals stun lasts 1 more turn            |

  Genesis awards, in order: Might, Zeal, Might, Life, Guarding, Life, Mending, Renewal, Haste, Peace, Haste (11 runes for 8 slots, so there is a choice). Saves from before runes drop their upgrade levels on load; stars and progress are kept.

- A "Verse Journal" collects every passage completed, so players can reread it outside of battle.
- **Passage map (2026-11-12):** passage select is an original parchment map of the Genesis 1–11 lands (The Deep, Eden, Land of Nod, Ararat, Shinar), drawn in code. Only won and playable locations show; winning reveals the next one once (trail draws itself, the hero walks it). Drag to pan; tap a location for its card and Begin.

### 2.6 Special attacks, Faith Ultimate, and Armor orbs

> **Revised 2026-11-12 (supersedes the orb-unlock rules below):**
>
> - **Armor is earned along the map.** The hero starts with only Attack. An angel (original character) presents each piece the first time its passage is won: Sword of the Spirit after passage 1 (the first battle), Shield of Faith after 5, Breastplate of Righteousness after 7, Sandals of Peace after 9, and the Full Armor of God ultimate after 10 (`unlocks` in each encounter file).
> - **Reading orbs give energy.** Each orb tapped during the reading is +1 ⚡ (3 orbs in passages 1–3, then 5). Energy carries into that fight.
> - **Specials cost energy** (Sword 3, Shield 2, Breastplate 3, Sandals 2; max 10) and can be used as often as energy allows, not once per fight. A wrong answer still spends the energy. The ultimate still uses the Faith meter.

The hero has **4 special attacks** and **1 Faith Ultimate**, themed on the armor of God (Ephesians 6:13–17). The names and effects are working drafts; all numbers are tuned by the balance simulation (§8.4).

| Ability                                | Unlocked by          | Powered effect (correct answer)                                                   | Base effect (wrong answer)               |
| -------------------------------------- | -------------------- | --------------------------------------------------------------------------------- | ---------------------------------------- |
| **Sword of the Spirit**                | Sword orb            | Heavy strike: 4× damage                                                           | 1.5× damage                              |
| **Shield of Faith**                    | Shield orb           | Normal hit, and blocks the next 2 enemy attacks                                   | Blocks the next enemy attack             |
| **Breastplate of Righteousness**       | Breastplate orb      | Heals 35% of max HP                                                               | Heals 15% of max HP                      |
| **Sandals of Peace**                   | Sandals orb          | Normal hit, and the foe loses its next turn                                       | The foe loses its next turn, with no hit |
| **Full Armor of God** (Faith Ultimate) | Full Faith meter (5) | 5× damage to the current foe and heals 20%. Needs no question. Meter resets to 0. | —                                        |

**Rules**

- Each unlocked special can be used **once per fight**. The ultimate can be used whenever the meter is full, so it can happen more than once in a long fight.
- **Attack** is always available, so a player who collected no orbs can still win.
- Specials are unlocked **for the next fight only**. The orbs have to be collected again for each encounter, which keeps the player watching the verse.

**Armor orbs (Scripture intro scene)**

- Each encounter defines which orbs appear (`orbs` in the content file). The early Genesis encounters introduce them gradually: 1 orb in the first fight, 2 in the next, and so on up to all 4. This works as a tutorial.
- Orbs appear **one at a time**, spread evenly across the narration. Each one floats up for about 4 s and then fades. The time scales with the text-speed setting.
- An orb may be **anchored to a key word** in the verse (`orbs[].word`): it rises as that word scrolls past and the word glows. This links the reward to paying attention to the text (Phase 2 stretch goal).
- A tap target of at least 64 px. A collected orb flies into its slot on the action bar, with a chime and haptic feedback.
- **Accessibility:** an "Auto-collect orbs" setting for players with motor difficulties.
- Skip forfeits uncollected orbs; Replay brings back uncollected orbs.

**Content schema addition**

```jsonc
"orbs": [
  { "special": "sword", "word": "created" },
  { "special": "shield", "word": "Spirit" }
]
```

Validation: `special` must be one of `sword | shield | breastplate | sandals`, with no duplicates. `word` (optional) must appear in the verse text.

#### Why stay on Phaser + Capacitor now that the game is mobile-first

| Option                              | Mobile                                                                            | Good fit for AI-written code?                                                                                                                                        | Verdict                                   |
| ----------------------------------- | --------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------- |
| **Phaser + TypeScript + Capacitor** | Good for a 2D turn-based game. It isn't GPU-heavy, so the WebView is fast enough. | **Best.** AI models write TypeScript/web code very reliably. Everything runs headless in Node and Chromium, so the AI can run tests and take screenshots on its own. | ✅ **Chosen**                             |
| Godot                               | Excellent native performance                                                      | Medium. GDScript is less familiar to AI and scenes are edited in a GUI editor.                                                                                       | Fallback if performance becomes a problem |
| Unity                               | Excellent                                                                         | Poor. Editor-centric, binary scene files, and slow and heavy for an agent to drive.                                                                                  | ✗                                         |
| SwiftUI/SpriteKit + Kotlin          | Best native feel                                                                  | Two codebases means double the AI work and double the bugs.                                                                                                          | ✗                                         |

The main mobile risk with Phaser is performance on low-end Android. We address it with texture atlases (2048×2048 max), at most about 3 particle emitters, and a performance budget that is tested on real devices (§8).

### 3.1 Architecture

```
src/
  main.ts                  # Phaser game config, scene registration
  scenes/
    BootScene.ts           # load assets, read save
    MapScene.ts            # chapter/stage select
    ScriptureScene.ts      # parallax run + scrolling verse + narration
    BattleScene.ts         # battlefield rendering, input, animations
    QuestionOverlay.ts     # question card UI (runs over BattleScene)
    ResultScene.ts         # victory/defeat recap
  core/                    # ★ PURE TypeScript: no Phaser imports, fully unit-testable
    battle/BattleEngine.ts # turn state machine, damage calc, combo, win/lose
    quiz/QuestionDeck.ts   # shuffle-without-replacement, difficulty filter
    progression/Progress.ts
    rng.ts                 # seedable RNG (deterministic tests)
  services/
    NarrationService.ts    # interface; TtsNarration + AudioNarration impls
    SaveService.ts
    ContentService.ts      # loads + validates content JSON
content/
  schema.ts                # Zod schemas
  genesis/
    001-creation.json
    ...
public/assets/             # sprites, backgrounds, audio
tests/
  unit/                    # Vitest
  e2e/                     # Playwright
```

**Key principle:** the scenes only _render_ and _forward input_. Every rule (damage, turn order, question selection, scoring) lives in `core/` as plain TypeScript that can be driven entirely by tests.

#### Battle state machine (`BattleEngine`)

```
INTRO → HERO_CHOOSE ─(attack | special)─▶ HERO_QUESTION → HERO_ACTION(powered|base) → CHECK_WIN
                    └─(ultimate)──────────────────────────▶ HERO_ACTION(ultimate)  ┘
      → ENEMY_ATTACK (skipped if stunned, absorbed if shielded) → CHECK_LOSE
      → HERO_CHOOSE … → NEXT_WAVE | VICTORY | DEFEAT
```

### 3.2 Content schema

> **Implemented in Phase 3 with one change:** encounter files store a `passage` reference (e.g. `"GEN 1:1-2"`) instead of verse text. The game resolves the text from the retelling source (`content/source/retelling/`) at load time, so verse text lives in one place. The draft below is kept for history; see `content/encounters/genesis/` and `src/core/content/schema.ts` for the real format.

```jsonc
// content/genesis/001-creation.json
{
  "id": "gen-001",
  "book": "Genesis",
  "reference": "Genesis 1:1-2",
  "translation": "WEB",
  "verses": [
    { "ref": "1:1", "text": "In the beginning, God created the heavens and the earth." },
    {
      "ref": "1:2",
      "text": "The earth was formless and empty. Darkness was on the surface of the deep and God's Spirit was hovering over the surface of the waters.",
    },
  ],
  "narrationAudio": null, // later: "audio/gen-001.mp3"
  "background": "bg_void",
  "waves": [{ "enemy": "shade_of_the_deep", "level": 1 }],
  "questions": [
    {
      "id": "gen-001-q1",
      "type": "multiple_choice",
      "difficulty": "easy",
      "prompt": "What did God create in the beginning?",
      "choices": ["The heavens and the earth", "The sun and moon", "Adam and Eve", "The animals"],
      "answerIndex": 0,
      "highlight": "God created the heavens and the earth", // phrase shown on wrong answer
    },
    {
      "id": "gen-001-q2",
      "type": "true_false",
      "difficulty": "easy",
      "prompt": "Before creation, the earth was full of light.",
      "answer": false,
      "highlight": "Darkness was on the surface of the deep",
    },
    {
      "id": "gen-001-q3",
      "type": "fill_blank",
      "difficulty": "medium",
      "prompt": "God's Spirit was hovering over the surface of the ____.",
      "choices": ["waters", "mountains", "garden", "sky"],
      "answerIndex": 0,
      "highlight": "hovering over the surface of the waters",
    },
  ],
}
```

**Validation rules** (enforced by `npm run validate:content` and in CI):

- Each `highlight` string must appear word for word in that encounter's `verses[].text`. This guarantees every question is grounded in the verse.
- At least 6 questions per encounter, with unique IDs across the whole game.
- `answerIndex` must be within the choices, and there must be no duplicate choices.
- Encounters within a book must follow canonical verse order.

## 5. UI / UX

- **Layout:** landscape is **locked**. Designed at 1280×720 with `Scale.FIT`, and the background extends to fill wider phones (19.5:9) with no letterboxing. Battle layout follows §1.3.
- **Safe areas:** HUD elements stay clear of the notch, Dynamic Island, and home indicator (CSS `env(safe-area-inset-*)` passed into the game).
- **Thumb zones:** answer buttons sit in the lower half of the screen within thumb reach. Nothing important is placed in the top corners.
- **Interruptions:** the game auto-pauses on app background or phone call and resumes on the same question.
- **Audio:** audio unlocks on the first tap (iOS requirement) and respects the device's silent switch for music while still letting narration play when enabled.
- **Performance budget:** 60 fps on an iPhone 11 and Pixel 6a; 30 fps minimum on a low-end Android device (about 3 GB of RAM). Cold start under 3 s. App size under 150 MB.
- **HUD:** wave pips (top), pause/settings (top right), hero portrait with HP and Faith meter (bottom left), **action bar** with Attack, 4 special slots and the Ultimate button (bottom right, thumb zone), damage numbers (floating).
- **Question card:** large tap targets (at least 48 px), readable font (at least 24 px at 720p), and the verse reference shown on the card.
- **Accessibility:** a text-speed slider, narration on/off, captions always on, a high-contrast option, colorblind-safe right/wrong feedback (icon plus color), and no reliance on the timer.
- **Audio:** music bed, SFX for hits and powered hits, narration ducking (music volume drops during the verse).

## 6. Content Authoring and Review

1. Pick the passage and add its kid-friendly retelling to `content/source/retelling/`, retold verse by verse from a public-domain translation (never from memory). **A human reviews every retold verse** for faithfulness. Record its narration with `scripts/audio/narrate.py`.
2. An AI agent drafts at least 6 questions per encounter using a fixed prompt template, and the same script also records the `highlight` phrases. **A human reviews every question** for accuracy and grounding before it is merged.
3. Run `npm run validate:content`.
4. Theological/content review: a checklist in the PR template.
5. Merge. The new encounter shows up in the map automatically.

## 7. Phased Approach

Each phase ends in something playable, deployed to a preview URL.

### Phase 0: Foundation (≈1 week)

- Vite + TypeScript + Phaser scaffold, ESLint/Prettier, Vitest, Playwright, and a GitHub Actions pipeline.
- **Capacitor iOS and Android projects**, landscape lock, safe-area handling, and app icon/splash placeholders.
- `CLAUDE.md` with the AI working rules (§11), plus a PR template with an acceptance checklist.
- `core/` folder with a seedable RNG and an empty `BattleEngine`.
- Debug URL params (`?scene=battle&encounter=gen-001&seed=42`).
- **Exit:** CI is green, and a blank game boots in the iOS Simulator, the Android emulator, and a preview URL.

### Phase 1: Battle vertical slice with placeholder art (≈2 weeks)

- `BattleEngine` state machine, damage, and waves, fully unit-tested.
- **The 4 special attacks and the Faith Ultimate** (§2.6) in `BattleEngine`: powered and base effects, once-per-fight use, shield, stun, heal, and the Faith meter. Fully unit-tested.
- `BattleScene` with rectangles or CC0 sprites: hero, one foe, HP bars, damage numbers, wave pips, Faith meter.
- **Action bar** (bottom right, thumb zone): Attack, 4 special slots (locked or unlocked), and the Ultimate button, which glows when ready.
- `QuestionOverlay` with multiple-choice questions; correct gives the powered action and wrong gives the base one.
- Because orbs don't exist until Phase 2, specials are unlocked with a debug param: `?specials=sword,shield,breastplate,sandals`.
- One hard-coded encounter (Gen 1:1–2).
- **Exit:** a full fight can be won or lost by answering questions, using every special and the ultimate.

## 8. Test Environment and Strategy

### 8.1 Test pyramid

| Level                  | Tool                                                                                        | What it covers                                                                                                                                                                                                                                                                                              |
| ---------------------- | ------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Unit**               | **Vitest**                                                                                  | `core/`: battle state transitions, damage math (normal vs powered), combo/special, wave progression, win/lose, `QuestionDeck` (no repeats until the pool is empty, difficulty filtering), progression and stars. The RNG is seeded, so results are deterministic. Target: at least 90% coverage of `core/`. |
| **Content**            | Vitest + Zod (`validate:content`)                                                           | Every JSON file matches the schema; highlights appear word for word in the verses; at least 6 questions; unique IDs; canonical order. Runs on every PR.                                                                                                                                                     |
| **Integration**        | Vitest + jsdom/headless Phaser                                                              | `ContentService` loading, `SaveService` round-trip, `NarrationService` with a fake TTS.                                                                                                                                                                                                                     |
| **End to end**         | **Playwright** (Chromium, WebKit, mobile viewport)                                          | Boot → Scripture scene → skip → answer correctly → see powered attack → win → result. Also the lose path and retry. Uses debug URL params and a `window.__TEST__` hook that exposes game state (e.g. hero HP, current question ID).                                                                         |
| **Visual regression**  | Playwright screenshots                                                                      | Battle HUD and question card at 1280×720 and phone landscape, compared against baselines. Animations are frozen with `?seed=…&freeze=1`.                                                                                                                                                                    |
| **Native smoke**       | **Maestro** (YAML flows) on the iOS Simulator and Android emulator                          | The app launches, landscape is locked, the full loop works, background/resume works, and saves survive an app restart. Runs nightly and before every store build.                                                                                                                                           |
| **Device performance** | Real devices via TestFlight / Play internal testing, plus an in-game FPS overlay (`?fps=1`) | The §5 performance budget on a low-end Android device and an older iPhone. Run once per phase.                                                                                                                                                                                                              |
| **Manual / playtest**  | TestFlight / Play internal builds + checklist                                               | Feel, readability, narration sync, age-appropriateness, thumb reach. Playtest with the target audience on their own phones at the end of each phase.                                                                                                                                                        |

### 8.2 Test hooks built into the game (debug builds only)

- `?scene=<name>&encounter=<id>`: jump straight to a scene.
- `?seed=<n>`: deterministic RNG.
- `?autoAnswer=correct|wrong`: answer questions automatically, to soak-test balance.
- `?specials=sword,shield,breastplate,sandals`: unlock specials without collecting orbs.
- `?faith=5`: start the fight with the Faith meter at that value (to test the ultimate).
- `?fast=1`: speeds up tweens and narration 10×.
- `?freeze=1`: disables idle animations for screenshots.
- `window.__TEST__`: read-only game state for Playwright assertions.
- All of these are stripped from production builds with `import.meta.env.DEV` guards.

### 8.4 Balance simulation

A Vitest script runs 10,000 simulated battles per encounter at answer accuracies of 30%, 60%, and 90% and reports win rates. Targets: about 60% accuracy wins at least 80% of the time, and 90% accuracy wins about 100% of the time. Struggling players can still win, so the game never blocks someone from moving on to the next passage.

## 9. Risks and Mitigations

| Risk                                                     | Mitigation                                                                                                                  |
| -------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------- |
| Art is the largest cost and timeline risk                | Build mechanics on placeholders first. See §11.3 for AI art options.                                                        |
| AI writes code that "passes" but is wrong                | Rules live in `core/` with high test coverage. A human reviews every PR. Screenshots and the e2e video are attached to PRs. |
| AI introduces Scripture errors                           | Verse text is imported from the source file only and checked word for word in CI (§6).                                      |
| WebView performance on low-end Android                   | Performance budget plus real-device checks each phase. Godot is the fallback (§3).                                          |
| App store rejection (kids, privacy)                      | Decide the audience early (§10). Follow the Phase 6 policy checklist from the start.                                        |
| Questions that aren't actually answerable from the verse | Automatic `highlight` check plus human review. Track accuracy per question after launch.                                    |
| TTS quality varies by device                             | Recorded narration (done 2026-11-23); captions always on.                                                                   |
| Translation licensing                                    | Retell only from public-domain translations, unless a license is obtained.                                                  |
| Doctrinal sensitivity                                    | Foes are abstract or temptation-themed; a content reviewer signs off on each arc.                                           |
| Players skip reading                                     | Questions require the verse, the replay button is always there, and stars reward accuracy.                                  |

## 11. AI-Driven Development

The game is mostly built by AI agents (Claude Code). The human acts as **product owner and reviewer**: deciding what to build, reviewing PRs, checking theology, playtesting on a phone, and handling store accounts.

### 11.1 What AI does and doesn't do

| AI does                                                                        | Human does                                            |
| ------------------------------------------------------------------------------ | ----------------------------------------------------- |
| All code, tests, CI, Fastlane setup                                            | Approves and merges every PR                          |
| Drafts kid-friendly retellings and questions                                   | Reviews every retold verse and question for accuracy  |
| Generates narration audio (neural TTS)                                         | Listens and spot-checks pronunciation (Hebrew names!) |
| Drafts store listings and screenshots                                          | Store accounts, signing certificates, submission      |
| Fixes failing CI and review comments                                           | Playtests on real phones each phase                   |
| **Never:** retells Scripture from memory, or ships content that isn't reviewed |                                                       |

### 11.2 Working rules (go into `CLAUDE.md`)

- **Small tasks:** each task is one GitHub issue with acceptance criteria and becomes one PR. Phases are split into tasks of about a day each.
- **Tests first for `core/`:** new rules come with unit tests. A PR without tests for new logic isn't merged.
- **Show, don't tell:** every UI PR includes Playwright screenshots at phone-landscape size (and simulator screenshots for native changes), so the reviewer can see the change without running it.
- **Determinism:** debug params (§8.2) let the AI reproduce any state headlessly and verify its own work.
- **Architecture guardrails:** no Phaser imports in `core/`; content only through `ContentService`; native features only behind service interfaces (so the web build and tests use fakes).
- **Content guardrail:** verse text comes only from `content/source/`. CI fails on any mismatch.
- **CI is the gate:** lint, typecheck, unit, content validation, e2e, and build must all pass before review.

### 11.3 Art options for an AI-built game

Animated character art is the hardest part to get from AI. Options, roughly in order of how consistent the results are:

1. **Purchased or CC0 2D asset packs** (cartoon fantasy heroes and monsters) as a base, recolored and adapted. Cheapest and most consistent. Check that the license allows commercial mobile apps.
2. **AI-generated character sheets + cutout rig:** generate one consistent design per character, split it into body parts, and animate with Spine/DragonBones or Phaser tweens (the bouncy chibi style in the reference works well this way). Check the image tool's commercial-use terms and the stores' AI-content disclosure rules.
3. **Commissioned artist** for the hero only, with AI or purchased art for backgrounds and foes.

Recommendation: start with option 1 for Phases 1–3, then decide between 2 and 3 for Phase 4 once the gameplay is proven.
